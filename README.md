# Crystal of Words — English Adventure

2D-платформер для вивчення англійської. Чистий HTML, CSS і JavaScript — без фреймворків, без npm,
без обов'язкового складання. Учень відкриває сторінку й грає.

---

### Два способи запуску

| | Що віддавати | Коли |
|---|---|---|
| **Розділений проєкт** | корінь репозиторію | GitHub Pages, локальний сервер. Картинки кешуються браузером, сторінка вантажиться швидше. |
| **Один файл** | `dist/index.html` | Надіслати комусь одним файлом, відкрити з флешки, показати без інтернету. |

Локально:

```bash
python3 -m http.server 8000      # далі відкрити http://localhost:8000
```

Відкривати `index.html` подвійним кліком теж можна, але браузер із `file://` не дає читати пікселі
картинки, тож **перефарбовані герої** (Ember, Moss, Dusk, Sand, Frost) виглядатимуть як звичайний
Azure. Гра про це попереджає в консолі й далі працює нормально. Сервер або `dist/index.html` цієї
вади не мають.

| Треба | Файл | Потім |

| додати граматичне питання | `data/grammar.js` | — |
| новий світ, предмет, буст, досягнення | `data/world.js` | — |

| правила гри, фізика, генерація рівня | відповідний файл у `src/` | — |
| стилі | `styles/game.css` | — |

`index.html` і ділять один глобальний простір імен — тому імпортів немає, але порядок важливий.

## Керування

| Дія | Клавіатура | Мобільний |
|---|---|---|
| Рух | `A` / `D` або `←` `→` | джойстик зліва (аналоговий) |
| Стрибок | `Space` / `W` / `↑` | ⤴ або джойстик угору |
| Суперстрибок (політ ~2 с, 5 разів за рівень) | `Shift` або `C` | 🚀 |
| Атака (діє на відстані ~170 px попереду, ловить і кажанів) | `F` або `J` | ⚔ |
| Взаємодія (колодязь, скриня, клітка, фініш) | `E` | E |
| Буст зі слота | `Q` | Q |
| Пауза | `Esc` | ⏸ |

### Керування на телефоні й планшеті

Джойстик **аналоговий**: легкий нахил — герой іде кроком, повний — біжить. Нахил угору теж стрибає,
як на геймпаді. Палець можна тримати й поза колом — рух не зупиняється, значення просто впирається
в максимум.

Увесь пад слухає **один трекер** (`tDown` / `tMove` / `tUp` у `src/engine.js`), а не окремий слухач
на кожну кнопку. Тому:

* палець можна **протягнути з однієї кнопки на іншу** — попередня відпускається, нова натискається;
* якщо палець з'їхав із кнопки, вона не лишається затиснутою;
* джойстик і кнопки працюють **одночасно** (різні пальці);
* `touch-action:none` + `preventDefault` прибирають прокрутку, зум подвійним тапом і затримку —
  саме через них керування раніше «слабко реагувало»;
* поворот екрана, згортання вкладки чи відкриття питання скидають усі затиснуті кнопки (`tWipe`).

Розміри за замовчуванням: джойстик 168 px, стрибок 104 px, атака 84 px, решта 76 px; уся група
піднята на 58 px від низу (`--tlift`). У **Settings** є два перемикачі:

* **Button height** — Low / Raised / High / Very high (24 / 58 / 96 / 140 px);
* **Button size** — Small / Normal / Large / Extra large (×0.85 … ×1.36).

Телефон у горизонтальній орієнтації (висота < 470 px) автоматично отримує нижчий і менший пад, щоб
кнопки не з'їдали рівень.

## Як додавати контент

**Нове слово** → у `data/vocabulary.js`, у потрібну тему і рівень (`lv[0]` easy, `[1]` medium, `[2]` hard):

```js
animals:{n:'Animals',lv:[ ['cat|🐱','owl|🦉'], [...], ['predator||an animal that hunts other animals'] ]}
```

Формат: `"english|емодзі|коротке англійське визначення"`. Обидва останні поля необов'язкові:
емодзі дає завдання з картинкою, визначення — завдання типу *Which word means this?*.
Для складного рівня визначення бажані (вони замінюють переклад).
З одного слова гра автоматично будує до 8 форматів завдань: picture → word, word → picture,
definition → word, listening, odd one out, correct spelling, missing letters, anagram, listen & type.

**Нова Vocabulary-тема** → новий ключ у `data/vocabulary.js`. Чекбокс у меню тем з'явиться сам.

**Нове Grammar-запитання** → у `data/grammar.js`, у масив потрібної складності:

```js
{k:'ch', q:'He ___ football.', o:['play','plays'], a:1, ee:'We add -s after he, she and it.'}
```

Типи `k`: `ch` — вибір варіанта, `in` — ввести відповідь (кілька варіантів через `|`),
`sq` — скласти речення (`a` — правильне речення), `er` — знайти помилку (`o` — слова, `a` — індекс помилкового).
`ee` — коротке англійське пояснення, яке гравець бачить після відповіді. Українських пояснень немає.

**Новий світ** → об'єкт у `WORLDS` (англійська назва, кольори неба/землі, набір ворогів, бос, тип місії `key` або `shards`).

**Новий монстр** → запис у `FOECFG` (розмір, hp, швидкість, `fly`/`shoot`) + гілка у `drawFoe()`.

**Нове спорядження** → об'єкт у `GEAR` + обробка ефекту там, де він потрібен
(`fight()` — зброя, `ask()` — шоломи, `movePlayer()` — черевики, `update()`/`hitBlock()` — амулети).

**Бонус за серію відповідей** → `STREAK_JUMP` і `STREAK_TIME` угорі файлу, нарахування — `applyStreakJump()`
у `record()`. 1 правильна відповідь = +25% висоти стрибка на 30 с, 3 поспіль = +50%, 5 поспіль = ×2.
Слабший рівень не перебиває сильніший, лише оновлює таймер. Множник — це висота, а не швидкість
(у коді береться `Math.sqrt(jumpMult)`, бо висота стрибка пропорційна квадрату початкової швидкості).

**Суперстрибок** → константи `SUPER_CHARGES` (кількість польотів), `SUPER_TIME` (тривалість у кадрах, 120 ≈ 2 с)
і `FLY_TOP` (висота зависання). Заряди видаються в `startLevel()`, логіка польоту — в `movePlayer()`,
активація — у `superJump()`. Черевики стрибка дають +1 політ.

**Новий буст** → запис у `BOOSTS` + кнопка в масиві `bl` усередині `ask()` (або обробка в `useFieldBoost()`).

**Новий мініквест** → додай гілку в `runQuest()`: намалюй свій HTML у `#quest-card`
і виклич `finish(true/false, 'повідомлення')`.

**Рунні камені** (💠, нескінченне джерело монет) → сегмент `'stone'` у `buildLevel()`, взаємодія — `runeStone()`.
Нагорода спадає з кожною відповіддю біля того самого каменя: 6 → 5 → 4 → 3 → 2 і далі по 2, тож рівень
завжди можна дофармити, але швидко «набити» монети не вийде. На рівні 4–6 каменів, один обов'язково перед
босом і один перед фінішем. Генератор також гарантує, що загальний запас монет на рівні щонайменше в 1.7 раза
більший за потрібний мінімум.

**Новий тип сегмента рівня** → додай `case` у `switch` всередині `buildLevel()` і додай його в `pool`.

## Графіка та звук

* **Паралакс у 3 шари** — власні силуети для кожної теми світу (`silhouette()`): ліс, кристали, дюни, гори,
  хвилі й щогли, будівлі з шестернями, вежі замку, вулкан, небесні острови, шпилі темного королівства.
* **Погода** для кожного світу (`WEATHER`): листя, іскри, піщані пориви, сніг, бризки, пара, привидні
  вогники, жар вулкана, хмари, темні порошинки.
* **Головний герой — намальований спрайт** (12 кадрів, нарізаних із твого аркуша й вбудованих у файл
  у `assets/hero-classic.png`): 5 кадрів бігу, стрибок, падіння, присідання після
  приземлення, атака мечем, отримання шкоди, стійка. Кадр обирається зі стану героя (`heroFrame()`),
  масштаб рахується автоматично від висоти кадру `idle` (`HERO_TARGET_H`, зараз 60 px), прив'язка — по
  ступнях. Якщо картинка чомусь не завантажиться, вмикається старий векторний герой (`drawPlayerVector`).
  Пил з-під ніг, аура бонусу стрибка, полум'я суперстрибка і смужка польоту малюються поверх спрайта.
* **Анімовані вороги**: слим стискається, кажан махає крилами, маг обертає кулю, голем гупає, привид
  хвилюється, мімік клацає кришкою, спалах при влучанні, шкала HP.
* **Бос** дихає, світить очима і **телеграфує атаку** (аура спалахує за мить до удару).
* **Ефекти**: тряска камери при ударах і появі боса, кільцевий вибух після перемоги над босом, «пуф» на місці
  монстра, пульсуючі кубики, обертові монети, вируючий портал, хвилястий прапор фінішу, віньєтка,
  червоний спалах при втраті серця, плавне затемнення на старті рівня.
* **Звук**: шаруваті SFX через WebAudio (стрибок, кроки, приземлення, монета, удар по кубику, правильна/
  неправильна відповідь, перемога над монстром, удар по босу, фанфари, поразка).
* **Процедурна музика** — окрема тема для кожного світу (`MTHEMES`: тональність, лад, гармонія, темп, тембр)
  з басом, арпеджіо, мелодією та ритмом; під час бою з босом вмикається швидша й агресивніша версія.
  У «Налаштуваннях» окремо вмикаються SFX і музика, гучність — Muted / Low / Medium / High.
* **Продуктивність**: віньєтка й ореол сонця запікаються в offscreen-canvas (`bake()`), градієнти будуються
  раз на рівень, усе поза екраном не малюється. Кадр (update + draw) — близько 3–4 мс у програмному
  растеризаторі, тобто із запасом для телефонів.

Меню → карта 10 світів → вибір тем (16 Vocabulary + 12 Grammar) → складність (Easy/Medium/Hard) →

## Ціна помилки: заморозка на 10 секунд

* **Одна відповідь на запитання.** Щойно гравець відповів, уся зона відповідей перестає приймати
  кліки (`body.style.pointerEvents='none'`), тож натиснути правильний варіант після неправильного
  вже неможливо — ні мишею, ні пальцем, ні поки партнер у co-op рятує відповідь.
* **Неправильна відповідь → 🧊 заморозка на 10 секунд** (`FREEZE_TIME=600` кадрів у
  `src/engine.js`). Протягом них не відкривається жодне запитання: ні блок, ні монстр, ні бос,
  ні рунний камінь 💠, ні колодязь із міні-квестом. Бігати, стрибати, збирати монетки й ухилятися
  можна — заморожені лише запитання.
* Видно це у трьох місцях одночасно: бокс `🧊 7s` у HUD, холодна рамка з підписом угорі екрана і
  сніжинки біля героя. У спільній грі партнер теж бачить над твоїм героєм `🧊 7s` — передається
  полем `fz`.
* Заморозка **не** настає, якщо помилку хтось поглинув: щит, шолом-охоронець, порятунок партнера
  в co-op або буст **🔄 Forgive a mistake**.
* Саме тому цей буст змінив зміст: раніше він давав відповісти ще раз (що суперечить правилу
  «одна відповідь»), тепер він прощає помилку — без втрати серця й без заморозки. Натискати його
  треба **до** відповіді.
* Час на паузі не спливає, тож перечекати заморозку в меню не вийде.

Хочеш іншу тривалість (наприклад, 5 с на Easy і 15 с на Hard) — це один рядок `FREEZE_TIME`
у `src/engine.js`.

## Формат завдань (вибір перед рівнем)

На екрані вибору складності є дві додаткові настройки — вони зберігаються між сесіями і їх видно
в брифінгу перед стартом.

**Як відповідати** (`S.opts.answer`):

| Режим | Що відбувається |
|---|---|
| **Choose only** | Кожне завдання — вибір варіанта. Нічого не треба писати: для молодших, для телефона, для швидкого раунду. |
| **Mixed** (типово) | Повний набір: картинки, аудіювання, правопис, пропущені літери, введення, порядок слів. |
| **Write it out** | Скрізь, де завдання це дозволяє, відповідь треба написати або скласти. Найскладніше й найкорисніше для правопису. |

Vocabulary ділиться на «натиснути» (`V_CHOICE`: pic, name, def, listen, odd, spell) і «написати»
(`V_TYPED`: letters, scramble, type), тож фільтр працює напряму.

Граматика фільтрується за типом питання. У режимі Choose only беруться лише `ch` і `er` — вони є
в **кожній** темі на кожному рівні, тож жодна тема не випадає. У режимі Write it out беруться `in`
і `sq`, а якщо в темі таких немає (18 із 36 комірок), звичайне питання з пропуском **перетворюється
на введення**: `He ___ football. | play; plays; playing | 2` стає «впиши слово» з відповіддю `plays`.
Перетворюються лише питання з `___` і короткою відповіддю без `/` — решта лишаються вибором
(`typableCh()`).

**Картинки** (`S.opts.emoji`): вимикають завдання з емодзі та прибирають емодзі з підказок і з
мініквесту з плитами. Корисно для старших груп і для власних списків слів без картинок.

Обидві настройки їдуть разом із кодом домашнього завдання і разом із запрошенням в онлайн-кімнату,
тож клас або пара гравців отримують однаковий формат.

### Перевірка написаних відповідей

`sameAnswer()` порівнює не рядки, а множини рівнозначних написань: апостроф прямий, кручений або
пропущений, `didn't` = `didnt` = `did not`, `can't` = `cannot` = `can not`, `I'm` = `I am`,
`he's gone` = `he has gone`, крапка в кінці та подвійні пробіли ігноруються. Регістр не має значення.
Помилка по суті (`studies` замість `study`, `is` замість `are`) так само не зараховується.

## Онлайн-гра (Play Together)

Два гравці, один рівень. Сервер кімнат **уже вбудований** у гру (Supabase-проєкт `yhekszqxheljbxoucalt`),
тож учень просто відкриває сторінку, створює кімнату й диктує код — нічого налаштовувати не треба.
У сторінці лежить лише `anon public` ключ, який саме для цього й призначений і дає доступ виключно
до Realtime-каналів. Таблиць, авторизації та SQL не потрібно.

Якщо колись знадобиться інший проєкт (наприклад, окремий для школи), у Play Together → Server можна
вставити свої *Project URL* і *anon public* ключ і натиснути **Test connection**; кнопка
**Use the built-in one** повертає все назад.

* **🏁 Race** — обидва біжать один і той самий рівень, бачать одне одного напівпрозорим силуетом
  з іменем і аватаркою; у HUD видно монети й прогрес суперника; наприкінці — порівняння часу, монет
  і точності.
* **🤝 Co-op** — спільна мета: монети йдуть у спільний гаманець, ключ, уламки кристала й бос
  зараховуються обом, а **помилка одного гравця передається другому** — партнер бачить те саме питання
  й може врятувати відповідь. Помилка все одно записується в статистику того, хто помилився
  (щоб адаптивне повторення працювало), але удару по грі не буде.
* **Приєднання одним посиланням.** Щойно господар створює кімнату, у лобі з'являється готове
  посилання виду `https://<сайт>/index.html#join=WX7K&m=coop` і кнопки **📋 Copy link**,
  **📤 Share** (де браузер це вміє) та **Copy the code only**. Партнер відкриває посилання — і вже
  в кімнаті: ні режиму, ні коду, ні тем обирати не треба, все приходить від господаря. Своїм
  лишається тільки особисте: ім'я, аватарка й герой (панель «🎭 You in this room» з кнопкою, яка
  веде на екран персонажа і назад у кімнату). Зміна героя чи імені в кімнаті одразу летить партнеру.
  Якщо кімната не відповіла (господар закрив гру), гість бачить «Try the room again» і код,
  підставлений у поле для ручного входу. Коли гра відкрита з диска (`file://`), посилання не має
  сенсу — замість нього показується код кімнати.
* **Формат завдань обирає господар кімнати.** У лобі є ті самі три режими відповідей
  (Choose only / Mixed / Write it out) і перемикач картинок. Вибір летить партнеру **одразу**, ще
  до старту (повідомлення `lobby`, поле `o`), і повторюється в `cfg` на старті рівня — тож обидва
  точно грають в одному форматі. Гість бачить його в себе в лобі рядком «Tasks».
* **Теми обираються прямо в кімнаті.** У господаря в лобі є список усіх уроків курсу, кілька
  вбудованих тем одним тапом, вибір складності й кнопка повного набору тем. Партнер бачить обраний
  урок і складність одразу, ще до старту — зручно, коли вчитель диктує код і пояснює, що буде.
* Хост створює кімнату з 4-символьним кодом і натискає Start — його світ, складність, теми, **seed**
  і навіть **власні уроки** розсилаються партнеру, тож рівень і слова в обох однакові, навіть якщо
  партнер твого курсу ніколи не бачив.
* Якщо партнер вийшов або зв'язок обірвався, гра продовжується соло з повідомленням.

### Транспорт

Клас `Realtime` — це прямий WebSocket до Supabase Realtime за протоколом Phoenix
(`wss://<проєкт>.supabase.co/realtime/v1/websocket?apikey=…&vsn=1.0.0`): `phx_join`, `broadcast`,
heartbeat кожні 25 с. Жодної бібліотеки з CDN — гра лишається одним файлом і онлайн працює навіть
при відкритті з локального файлу.

Присутність гравців зроблена самою грою: кожні 2 секунди летить маленький `hi`, і якщо від партнера
нічого не чути понад 7 секунд, він вважається відключеним. Це навмисно не покладається на
server-side presence.

Уся ігрова логіка ходить через `NET.send` / `NET.onMsg`, тому транспорт можна замінити, не чіпаючи
гру.

### Скільком пакетів і як згладжується рух партнера

Supabase Realtime за замовчуванням пропускає ~10 повідомлень на секунду на канал, тому:

* позиції йдуть рівно 10 разів на секунду (`netTick`, поріг 100 мс);
* якщо герой не рухається, пакет летить раз на 600 мс — просто «я тут»;
* зміни монет/сердець (`netStat`) і спільні монети в co-op (`netCoin`) складаються в один пакет
  раз на 400 мс, а не по пакету на кожну монетку.

Екран малюється 60 разів на секунду, а пакети приходять 10 — тому партнера **не** малюють там, де
впав останній пакет. Кожен пакет отримує час приходу (`netPos` → `NET.buf`), а `mateAt()` малює
привида на ~130 мс у минулому й плавно веде його між двома сусідніми пакетами. Якщо один пакет
загубився — рух продовжується за швидкістю ще до 200 мс; якщо тиша понад 1,2 с — привид
зупиняється, стає прозорішим і показує «📶 X.Xs», а бокс `🌐` у HUD червоніє.

Окремо передається прапорець `b` (партнер відповідає на питання) і `fly` (суперстрибок). Поки
відкрите питання, фізика партнера навмисно стоїть — тепер над ним видно «💭 thinking», щоб пауза не
читалась як зависання.

**Безпека.** У сторінку потрапляє лише `anon public` ключ — він і створений для того, щоб бути в
клієнті. **Ніколи не встромляй сюди `service_role`.** Для гри варто завести окремий Supabase-проєкт,
де немає інших даних.

## Однакові рівні: seed

Генерація рівня детермінована: `withSeed(seed, () => buildLevel(world, diff))`. Той самий seed завжди
дає той самий рівень — ті самі кубики, монстри, колодязі й бос. Це основа і для мультиплеєра, і для
домашніх завдань. `SESSION.pin = true` означає «цей seed зафіксовано» (домашка або онлайн-кімната);
у вільній грі seed щоразу новий.

### Завдання на слова без прослуховування

На твоє прохання тип завдання «прослухай і повтори слово» більше не генерується, якщо в слова є
англійське визначення (а воно є в усіх 1055 слів обох курсів): замість нього гра показує визначення
і просить обрати або написати слово. Кнопка 🔊 лишилася на кожному питанні як підказка, а не як
завдання. Правка в `src/questions.js`.

### Правильна відповідь більше не стоїть першою

Варіанти граматичних питань тепер перемішуються під час гри (`src/questions.js`). До цього вони
йшли в тому порядку, у якому записані в курсі, а записані вони майже завжди з правильним варіантом
першим — тобто уважний учень міг проходити граматику, не читаючи речення. Виняток — завдання
«знайди помилку»: там варіанти є частинами речення, і їх порядок зберігається.

### Як додати решту курсу

Один файл на юніт у `authoring/course-upper/`, формат описаний у
`authoring/course-upper/FORMAT.md` (слова: `слово|емодзі|англійське визначення`; граматика: рядок
на питання, перший символ задає тип). Перевірка одного файлу:

```
python3 tools/check_section.py authoring/course-upper/u05.py
```

Збірка обох курсів: `python3 tools/build_course.py`. Нові курси додавай **у кінець** списку
`COURSES` у цьому скрипті й у кінець списку `<script>` в `index.html` — від порядку залежать ключі
уроків (`cv:b1.0.0`), на які посилаються збережені вибори тем і коди домашніх завдань.

## 📚 Бібліотека курсів (вибір уроків, розділів, курсів)

Окремий екран `s-lessons` (`src/lessons-ui.js`) — дерево на три рівні з галочкою на кожному:

```
☑ English 10–12 · Intermediate            10 units · 44 lessons
  ▾ – Unit 1 · Me and My World                     5 lessons
        ☑ Lesson 1 · Free-time activities   📘 12 · 📐 20
        ☐ Lesson 2 · Around the world       📘 14 · 📐 20
☐ My club course                     my course · 2 units
```

* Галочка на **уроці**, на **розділі** й на **курсі** — це одна й та сама дія, просто різного обсягу.
* Можна тримати ввімкненими **кілька розділів і кілька курсів одночасно** — свій і вбудований разом.
* Частково обраний розділ чи курс показує «–» (жовтим), повністю обраний — «✓» (бірюзовим).
* Перемикач зверху вирішує, чого стосується галочка: **📘📐 Words + grammar**, **📘 Words only**
  або **📐 Grammar only**. Тобто слова можна взяти з одного уроку, а граматику — з іншого.
* Пошук фільтрує по назвах курсу, розділу й уроку і сам розгортає знайдене.
* Біля кожного уроку видно, скільки в ньому слів і граматичних завдань, а зверху — підсумок
  («8 lessons from 3 units in 2 courses · 📘 75 words · 📐 112 grammar tasks»).

Бібліотека **нічого не зберігає окремо**: галочка — це просто `SESSION.topics.v` / `.g`, ті самі
масиви, що й чипси тем. Тому рівні, домашка одним кодом і онлайн-кімната працюють без змін.

Заходи до неї два:

* **Learning topics → «Open the course library»** — для звичайної гри; на екрані тем видно рядок
  з підсумком і кнопку «Remove all lessons».
* **Play together → «📚 Courses, units and lessons»** — для кімнати. Тоді кожна галочка **одразу**
  летить партнеру (`sendPlan`), а кнопка внизу підписана «Send N lessons to the room». Швидкий
  вибір одного уроку через `<select>` у лобі лишився для випадків, коли треба саме один урок.

## Мої курси (редактор контенту)

Розділ **My Courses & Words** → «My courses»: курс → секції (юніти) → уроки. Кожен урок має свої слова й граматику
і його можна запустити окремо, разом із секцією або як весь курс. Власний контент зливається з
вбудованими банками (`syncCourses()`), тому проходить через ті самі формати завдань — картинки,
аудіювання, правопис, зайве слово тощо — без окремого коду.

Формат слів (один рядок — одне слово):

```
kitchen | 🍳 | the room where you cook
stairs  |    | steps that take you up to the next floor
roof
```

Формат граматики (один рядок — одне питання):

```
He ___ football. | play; plays; playing | 2 | We add -s after he, she and it.
? Make it negative: "He is happy." | he is not happy; he isn't happy | Add not after be.
! She don't know. | She; don't; know | 2 | Third person needs doesn't.
# The train leaves at six | Present Simple for timetables.
```

`?` — учень вводить відповідь (кілька написань через `;`), `!` — учень тикає на помилку,
`#` — учень складає речення. Без префікса — звичайний вибір, число вказує правильний варіант.

Курси експортуються та імпортуються як JSON (`{"courses":[…]}`), тож ними можна ділитися з колегами.
Кнопка **Load example course** додає готовий приклад із правильним форматом.

## Персонаж і аватар

Розділ **Character & Avatar**: ім'я (видиме партнеру в онлайні), аватарка-емодзі та вибір героя.

Кожен герой або посилається на аркуш спрайтів у `SHEETS`, або є простим векторним. Зараз аркушів два:

* **classic** — перший намальований герой. Шість варіантів (Azure, Ember, Moss, Dusk, Sand, Frost) —
  це один і той самий аркуш із перефарбованою бронею: `tintSheet()` зміщує відтінок лише синіх
  пікселів, тож волосся, шкіра й шарф лишаються як намальовані.
* **sensei** — старий маг-наставник, 14 кадрів: біг (5), стійка, стояння, присідання, стрибок,
  падіння, атака з магічною кулею, шкода («!»), роздуми («?») і поразка. Він трохи вищий за
  звичайного героя (66 px проти 60), щоб одразу було видно, хто веде гру.

Кадр обирає `heroFrame(meta)`, і **зайві пози використовуються лише тоді, коли вони є в аркуші**:
Сенсей задумливо чухає бороду, поки на екрані питання, і лежить із привидом, коли серця закінчилися;
звичайний герой у тих самих станах просто стоїть.

### Герой для вчителя

Сенсей позначений `mentor:true` і має плашку **teacher** у виборі персонажа. У кімнаті спільної гри
господар (тобто вчитель) має кнопку **🧙 Teach as the Sensei** — один тап, і партнер одразу бачить
нового героя над ім'ям. Механічних переваг у Сенсея немає: це роль, а не перевага.

Додати наступного намальованого героя = додати аркуш у `SHEETS` і запис у `HEROES` з полем `sheet`.

## Стабільність

Рівень не може «залипнути»: питання й квести захищені кількома запобіжниками.

* `askActive` — друге питання ніколи не перезаписує відкрите (раніше це залишило б гру чекати на відповідь,
  якої вже немає в DOM).
* Watchdog у `loopStep()` — якщо `LV.busy` тримається понад ~2.5 с, а жодного діалогу на екрані немає,
  рівень автоматично розблоковується (`unstick()`).
* Усі асинхронні обробники (`hitBlock`, `fight`, `bossAttackTry`, `interact`, `runeStone`, `runQuest`)
  загорнуті в `try/catch` — помилка всередині не залишає гру заблокованою.
* Глобальні `error` і `unhandledrejection` теж викликають `unstick()`.
* `clearKeys()` скидає стан клавіш і екранних кнопок при відкритті/закритті діалогу, при `blur` і при
  перемиканні вкладки — затиснута клавіша більше не «залипає».
* Перехід у фонову вкладку ставить рівень на паузу і зупиняє музику; планувальник музики не робить
  «залпу» нот після повернення.
* `speak()` не накладає озвучки одна на одну (`cancel()` + невелика затримка) — це типова причина зависань
  Web Speech у Chrome при швидких повторах.

## Ліцензія на графіку

Спрайт героя взято з аркуша, який ти надав. Перед публічним релізом варто перевірити ліцензію цього
набору — гра розповсюджує зображення разом із кодом (`assets/*.png`, а в однофайловій збірці вони
вбудовані в `dist/index.html`).

## Наступні кроки після MVP

1. Більше контенту: решта Grammar-тем зі списку, 2000+ слів, англійські визначення для medium-рівня, власні картинки замість емодзі.
2. Спрайти та анімації замість векторних форм; окрема музика для кожного світу.
3. Режими Boss Rush, Endless Run, Classroom Mode, Custom Level.
4. Supabase/Firebase: акаунти учнів, класи, домашні завдання, хмарна статистика.
5. Редактор рівнів і власних наборів слів для вчителя.
6. PWA-режим (offline, іконка на телефоні).
